---
title: Responsible disclosure
---

If you discover a security vulnerability in TBV — in the contracts, the off-chain services, or the cryptographic protocol — please report it privately through the channel below. Responsible disclosure protects users while a fix is prepared and deployed.

## Do not disclose publicly

Please **do not** open a public GitHub issue, post in community channels, or otherwise disclose a suspected vulnerability publicly before it has been triaged and resolved. Public disclosure of a live vulnerability puts real user funds at risk. Coordinate with the team first.

## How to report

| Item | Detail |
|---|---|
| Security contact (email) | To be announced at launch |
| PGP public key | To be announced at launch |
| Expected acknowledgement | To be announced at launch |
| In scope | To be announced at launch |
| Out of scope | To be announced at launch |

When reporting, please include as much of the following as you can:

- A clear description of the issue and its impact.
- Affected contract, service, or component (with commit hash or address where possible).
- A minimal proof of concept and reproduction steps.
- Expected versus actual behavior.

Encrypt sensitive details to the published PGP key once it is available.

## Scope

The intended scope spans the on-chain contracts, the off-chain operator services, and the cryptographic protocol (the pre-signed Bitcoin transaction graph, WOTS commitments, the BABE construction, and the SP1 + Groth16 proof pipeline). Exact in-scope and out-of-scope boundaries are **to be announced at launch**.
